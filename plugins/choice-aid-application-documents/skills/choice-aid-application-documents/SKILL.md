# choice aid 応募書類作成

このスキルは履歴書・職務経歴書の作成専用。面接官の採点や共有FBシートへの登録は行わない。

## 入力と出典

1. Indeed等の履歴書・レジュメPDF：氏名、ふりがな、連絡先、生年月日、学歴、職歴、資格、本人写真の根拠。
2. Gemini面接メモと逐語録：本人の発言、仕事内容、工夫、志向の根拠。AI要約の誤記を逐語録で確認。
3. CA手打ちメモ：面談時の補足。曖昧な略語・年月は本人確認前に確定しない。
4. `中途人材＿求職者管理表`：指定Drive ID `1AkIYX56cig3FxCetRC5YzHBONXTBZQ6gbQF_pW5W8o8` の現在版XLSX。対象者の `案件管理` と `選考管理` のみ。該当行がなければ他資料で続行。Driveを読めない環境では、担当者から該当行またはXLSXを受け取る。
5. 応募先求人票があれば企業別の職務要約・自己PRの訴求材料に使う。なければ汎用版を作る。

元資料の食い違いは出典別に並べ、本人確認が必要な項目にする。管理表の年齢から生年月日を逆算しない。提案・推薦した企業を勤務先とみなさない。実績、資格、退職理由を創作しない。

## 手順

1. 対象者の氏名と担当CAを確定し、資料を読む。`references/input-and-checks.md` を参照。管理表は氏名を完全一致（空白のみ正規化）で照合。同姓同名の選考行を混ぜない。
2. 氏名・ふりがな・生年月日・住所・電話・メール・学歴・職歴・資格・担当業務・実績・希望条件の事実台帳を1回作る。各値に出典を残す。
3. PDFの顔写真は `scripts/extract_resume_photo.py` で抽出できる。抽出した画像を目視して本人写真と確認する。候補が複数、またはスキャンPDFだけなら自動選択しない。`photo_path` にローカルの画像を指定する。
4. `assets/resume-template.xlsm` と `assets/career-template.docx` の作業コピーを候補者ごとに作る。原本は変更しない。`references/input-and-checks.md` のJSONを用意し、`python scripts/build_application_sources.py candidate.json output_dir` を実行する。XLSXには原本の記入欄を覆わない右側N2へ写真が入る。マクロは実行しない。
5. 生成されたXLSXをGoogle Driveで**Googleスプレッドシート形式に変換**し、DOCXを**Googleドキュメント形式に変換**する。Driveへ作成・変換する権限がない環境では、XLSX/DOCXを担当者に返し、変換が未実施と明示する。PDFを標準納品にしない。
6. ネイティブファイルの本文と写真を読み戻し、印刷・改ページ・文字化けを確認する。氏名、メール、電話を原資料と1文字ずつ照合する。確認できない項目は別の要確認リストへ。本人と作成CA・別担当者のチェックが終わるまでは「確認用ドラフト」とする。

## 出力

- 履歴書：GoogleスプレッドシートURL、写真の有無、ドラフト状態。
- 職務経歴書：GoogleドキュメントURL、汎用版か企業別版か、ドラフト状態。
- 本人に確認が必要な事項と資料間の不一致を短く列挙。
- Google形式へ変換できない場合は生成XLSX/DOCXを添付し、未変換と明記。

## 境界

本人未確認の同意・既往歴・犯罪歴の宣誓・署名は代理入力しない。管理表の他候補者・KPI・想定売上・返金条件は抽出しない。候補者JSON、写真、完成書類をスキルフォルダへ保存しない。書類作成後に作成CAと別担当者が提出前確認を行う。
