# choice aid｜面接FB・求職者プロファイル（v1.3）

履歴書・職務経歴書の作成を頼まれたら、このスキルではなく別スキル `choice-aid-application-documents` を使う。

## 守ること
1. 点数は**面接官の質問・進行の品質**。求職者の能力・採用可否や、年齢・性別などの属性に点をつけない。
2. 入力にある事実だけを使う。Gemini要約は誤記しうるので逐語録で確かめ、資料どうしの食い違いは両方書いて「要確認」。本人申告（ハラスメント等）は事実と断定しない。値を作らず「未確認」「未記載」「評価保留」を使い分ける。
3. 個人情報は最小限。電話・メール・詳しい住所・生年月日・健康情報の詳細は書き写さない（住所は市区町村・最寄駅・通勤範囲まで）。ナレッジに氏名や個別のエピソードを残さない。
4. 登録先は全CA共通の1つのシート「中途人材紹介_AI面談FB」（ID `1dIJ5reidWBJqUL76bwY77kHvoKPfJWXTwj940-aYJFg`）だけ。CA別のコピーや代わりのシートを作らない。ユーザーがテスト環境のシートIDを明示したときだけそこへ書く（ファイル名に「テスト環境」を含むことを確かめる）。
5. **採点はシートを読む前に終える**。シートや管理表で前回の点数・評価が目に入っても、点数を変えない。

## 手順（途中で質問せず最後まで進める。必須情報が1つだけ欠けるときだけ1問聞く）
**Step 1｜3資料を読む**：Geminiメモ（要約と逐語録）・Indeedレジュメ・手打ちメモをすべて読む。日時・面接官（発話から判断し、出席者一覧で決めない）・求職者・企業・区分（自社採用／CA面談／ロープレ）を確定し、事実（学歴、各社の時期・雇用形態・業務・実績・入退社理由、ツール、希望条件、他社状況、次回連絡）と、矛盾・不足を整理する。

**Step 2｜採点**：`references/scoring-rubric.md` で8項目を採点する（5点刻み、根拠の時刻つき）。工程がなかった項目は空欄の保留にし0点にしない。総合点は計算式どおりに出す。

**Step 3｜FBとシート用データを作る**（3資料だけで作る）
- 画面用FB：`references/output-format.md` の型。良い点3、改善点3（事実→課題→次の行動→効果）、次回質問3〜5（確認目的・判断基準つき）。
- シート用データ：14タブ分（タブと件数は `references/sheet-registration.md` の表）。候補者プロファイルは44列すべてを、転職動機の変遷・強み・求人判断との関係が分かる文章で埋める（単語の羅列にせず、各列を根拠つきの文章で書く）。職歴は古い順に1雇用区分1行（同じ会社でもインターンと社員は分ける）。追加ヒアリングは質問の形で目的・求人選定への影響・優先度をつける（手打ちメモで回答済みのものは未確認に戻さない）。企業マッチングは実際に応募・紹介した企業だけで、求人票がなければ保留。育成カルテ2〜3、アクション3〜4（担当・優先度・期限の根拠・確認方法）、改善・質問ナレッジ各2〜3は汎用化して書く。
- 列名はStep 5で読むシートの1行目に合わせる。シートを読めないときだけ `references/sheet-columns.json` を見る。

**Step 4｜求職者管理表で補う**（読み取り専用。書き戻さない）
- 正本はDrive ID `1AkIYX56cig3FxCetRC5YzHBONXTBZQ6gbQF_pW5W8o8`。テスト時はユーザーが指定したテスト用の管理表IDを使ってよい。
- 2段階で読む：①`案件管理`・`選考管理` の1行目と「求職者名」「求職者ID」の列だけ → 対象者の行番号を決める（氏名は空白だけ正規化して完全一致。同姓同名が複数なら結合しない）→ ②その行だけ読む。他の求職者の行は読まない。シートとして読めないXLSXなら `scripts/extract_candidate_management.py 管理表.xlsx 求職者名 [担当CA]` で対象行だけ取り出す。該当なしなら空のまま進む。
- 使うのは希望条件・CA備考・提案企業別の選考状況だけ。プロファイルと求人提案管理を補い、3資料と食い違えば「要確認」を足す。**点数とFBは変えない**。提案・推薦・内定・入社を混同しない。`今日対応`・KPI・想定売上は使わない。

**Step 5｜シートに書く**：`references/sheet-registration.md`（読む範囲・追記行・数式・同時書き込み・書けないとき）と `references/id-rules.md`（ID）に従う。シートの読み取りは「まとめ読み1回 → 書き込み直前の確認1回 → 書いた範囲の読み戻し1回」だけ。

**Step 6｜報告**：画面用FBを出し、続けて登録結果（タブごとの範囲・件数・ID、書けなかったタブと理由）を出す。44列などシート用の長い内容は画面に全文出さない。

## 最後のチェック
- [ ] 逐語録まで読み、話者を取り違えていない。資料の食い違いを要確認にした
- [ ] 8項目×配点で総合点を計算し直した。保留を0点にしていない
- [ ] 良い点・改善点に時刻と行動の根拠がある。録画を見ていないのに表情・声を断定していない
- [ ] 44列すべてに事実か「未確認」が入っている。求人票のないマッチングは保留
- [ ] 電話・メール・詳しい住所がない。ナレッジに氏名がない
- [ ] 登録先IDが正しい。IDの重複や、他CAの行・数式の上書きがない。必須の5タブがそろった
- [ ] 読み戻しで確かめたタブだけを「登録済み」と報告した
