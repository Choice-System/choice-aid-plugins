# ID規則 v1.0（2026-10-18制定）

全CA・全AIで同じ規則。**IDに氏名・ローマ字名を入れない。** 記録どうしは各行の `面接ID`／`評価ID` 列で紐づける（詳細FB・育成カルテ・成果連携は評価ID、職歴・追加ヒアリング・企業マッチング・求人提案・アクション・改善ナレッジは面接ID）。

| 種類 | 形式 | 例 | 採番の範囲 |
|---|---|---|---|
| 面接ID | `IV-YYYYMMDD-NN` | `IV-20261014-02` | 面接日ごとに01から。全CA共通 |
| 面接前の準備記録 | `PRE-YYYYMMDD-NN` | `PRE-20261016-01` | 作成日ごと。面接後は新しい `IV-` を振り、備考に元の `PRE-` を書く |
| 評価ID（実面談） | `EV-` ＋面接IDの日付・番号 | `EV-20261014-02` | 面接IDと1対1。別に数えない |
| 評価ID（ロープレ） | `EV-YYYYMMDD-RNN` | `EV-20261020-R01` | 実施日ごとにR01から |
| タスクID（アクション管理） | `ACT-NNN` | `ACT-035` | タブ全体の通し番号 |
| ナレッジID（改善ナレッジ） | `KN-NNN` | `KN-035` | 同上 |
| 質問ID（質問ナレッジ） | `Q-NNN` | `Q-033` | 同上 |
| 課題ID（個別育成カルテ） | `AR-NNN` | `AR-017` | 同上 |
| 求職者ID（将来） | `C-YYYYMM-NNN` | `C-202610-012` | 進捗管理側で発番。FB側は列ができたら転記 |

- `YYYYMMDD` は面接の実施日（日本時間）。登録日ではない。`NN`・`NNN` はゼロ埋めし、超えたら桁を増やす（`ACT-1000`）。
- 旧形式（`CA-20261008-001`、`EV-MASUDA-20261009`、`ACT-KUSAKA-01` など）は新しい登録で使わず、番号の計算にも入れない。

## 採番（`sheet-registration.md` の「まとめ読み」で取ったID列を使う）
1. 面接ID：`面接ログ`・`面接評価`・`求人選定_候補者プロファイル` のID列で、同じ日付の `IV-YYYYMMDD-NN` の最大番号＋1。無ければ `01`。
2. 評価ID：面接IDの `IV-` を `EV-` に変えるだけ。
3. 子ID（`ACT-` `KN-` `Q-` `AR-`）：そのタブのID列で、形式に合う値の最大番号＋1から順に振る。
4. 書き込み直前の確認と、他のCAと重なったときの扱いは `sheet-registration.md`「同時書き込み」。
